Select AWS HealthOmics as the primary global genomics-execution platform if China-resident genomes can remain in a separate China-local architecture, because it is the only named hyperscaler service here that currently combines managed WDL, Nextflow and CWL execution with petabyte-scale omics storage.[1][2][3] Use Google Cloud Healthcare API plus Terra where researcher collaboration, GATK-adjacent workflows and shared workspaces outweigh the need for a single hyperscaler-managed genomics service.[4][5] Do not select Microsoft Azure Genomics as a managed-service option, because it retired on January 7, 2025; Azure remains viable only with a customer-operated workflow stack.[6][7] A narrow AWS Ready2Run GATK workflow model is $1.0 million per year for 100,000 genomes, versus Google’s illustrative compute-and-retained-storage model of $1.076 million, but neither is an all-in comparable production price and egress, storage, software licenses and clinical-data services can materially exceed the apparent difference.[8][9][10] No platform creates one lawful pooled HIPAA, GDPR and China genomics environment; simultaneous compliance requires segregated US, EEA and China processing zones, with China-originating genomic data retained locally unless the applicable HGR and CAC/PIPL transfer route is authorized.[11][12][13][14][15]

### AWS (Healthlake, HealthOmics)

AWS divides the architecture cleanly. HealthLake is the clinical-data and FHIR interoperability layer. HealthOmics is the genomics workflow, omics storage and analysis layer. A biotech that treats HealthLake as the variant-calling service will build the wrong platform.

HealthLake is a HIPAA-eligible service to store, transform and analyze health data using FHIR APIs; it is a managed FHIR R4 health-data service for storing, analyzing and sharing clinical data.[18][16] AWS describes it as an AI-ready FHIR persistence layer for fragmented clinical data, with petabyte-scale performance, clinical-data transformation, FHIR APIs, SMART on FHIR authorization, Bulk Data export, and medical NLP. Its relevant role is phenotype, diagnosis, medication, laboratory, care-pathway and clinical-report context around a genomic result.[16][54][55] It can be combined with HealthOmics and HealthImaging for multimodal precision-medicine analysis.[16][55][56]

HealthLake is currently available through the AWS Console and documented endpoints in US East (Ohio and N. Virginia), US West (Oregon), Asia Pacific (Mumbai and Sydney), Canada Central, Europe (Ireland and London). The endpoint table lists FIPS endpoints for US East (Ohio), US East (N. Virginia) and US West (Oregon).[54][57] HealthLake became generally available in supported Regions on July 15, 2021; Dublin availability was added on June 9, 2025.[58] Its FHIR import architecture has operational limits: one concurrent import job and one concurrent export job per supported Region, up to 1,000,000 files and 5,000 GB total per `StartFHIRImportJob`, and a 50-GB per-file import limit.[57] These limits govern clinical-data ingestion and export, not whole-genome workflow throughput.

HealthOmics is AWS’s purpose-built omics platform. AWS defines three components: Workflows for automatically provisioned bioinformatics compute, Storage for petabyte-scale omics data, and Analytics for multiomics and multimodal preparation.[1] It supports genomic, transcriptomic and other omics data at scale; AWS explicitly lists genomic analysis, variant calling, multiomics research and precision medicine as intended uses.[18]

HealthOmics supports WDL, Nextflow and CWL private workflows. Existing pipelines in any of those languages can use the same underlying compute, storage and networking capabilities without a language rewrite.[2][3] Current language support includes Nextflow versions v22.04, v23.10, v24.10, v25.10, v26.04 and v26.10; WDL 1.0, 1.1 and development; and CWL 1.0, 1.1 and 1.2.[3] The service executes containerized tasks with defined compute specifications, and customer workflow definitions may call AWS services through IAM roles, including S3, ECR and CloudWatch.[1][2]

HealthOmics WDL execution offers conformant and lenient modes. Workflow definitions specify task inputs, outputs, compute, memory and accelerators; HealthOmics manages engine execution, task dependencies, data movement, retries and resource allocation. [190][179][193]

For a new customer, HealthOmics has an important availability boundary. AWS closed Variant Store and Annotation Store to new customers on November 7, 2025; existing customers can continue to use them. Sequence Store and Workflows remain open to new customers.[18][59][60] A new AWS design therefore cannot assume access to managed HealthOmics VCF cohort storage or annotation stores. It should plan for Sequence Store, S3, private workflow outputs, and another governed cohort-query architecture unless it already has the relevant HealthOmics analytics entitlement.

HealthOmics Storage supports reference and raw sequencing data in FASTA, FASTQ, BAM, uBAM and CRAM formats, preserving metadata such as file linkages, alignments, base counts, indexes, protocol and custom tags.[61] Sequence Stores support KMS encryption, access permissions and read-set attribute-based access control.[1] HealthOmics automatically compresses and moves inactive read sets to Archive after 30 consecutive days without access; archived read sets must be activated before use, while active read sets are immediately accessible.[61]

Sequence Store also provides indexing, versioning and `omics://` genomic URIs. [190][194][181]

HealthOmics workflows can address Sequence Store read sets and references through `omics://` genomic URIs, reducing the need for customer-managed exports and repeated staging of FASTQ, BAM and CRAM files.[190][179][181]

AWS describes HealthOmics as scaling beyond 100,000 concurrent vCPUs and supporting tens of thousands of tests daily.[1] That is a service-capacity statement, not a per-pipeline benchmark. For submission at the requested scale, HealthOmics batch operations permit up to 100,000 runs in one `StartRunBatch` request, with per-run parameters supplied in an S3 JSON file.[62] Batch submissions are gradual and asynchronous and share the same StartRun throughput quota as direct runs.[62]

Default quotas require production planning. HealthOmics defaults to 50 concurrent dynamic-storage runs, 10 static-storage runs, 25 concurrent tasks per run, 12 active GPUs and 5 StartRun transactions per second per Region. In us-east-1 and us-west-2, increases up to 100 concurrent tasks per run and up to 500 active GPUs are automatically approved; these quotas are adjustable.[63] A 100,000-genome program should seek quota approval before a production commitment and should model completion time using the actual workflow’s task graph, GPU demand, scratch footprint and retry behavior.

HealthOmics supplies two workflow paths.

- **Ready2Run workflows:** These are third-party published, preconfigured workflows. They are useful where the scientific method, input size, containers, compute and storage profile fit the supplied pipeline. [23][64] They cannot be edited; users cannot change compute resources, run storage, containers, workflow definitions or maximum input size. Ready2Run workflows cannot be shared or assigned to run groups, and batch submission is not supported. [65][62]

- **Private workflows:** These let the biotech package its own pipeline in WDL, Nextflow or CWL, select containers and resources, share workflows across accounts in the same Region, use run groups, caching and batch submission, and preserve immutable workflow versions. [2] This is the appropriate route for a regulated production pipeline needing validated containers, fixed references, version control, a controlled retry policy and a 100,000-sample submission plan.

Private HealthOmics workflow images can be sourced from Docker Hub, Amazon ECR, GitHub, GitLab, Google Artifact Registry or Container Registry, Azure Container Registry, NVIDIA NGC, Quay and Seqera Containers. [180]

The Ready2Run catalog includes AlphaFold workflows for proteins of up to 600 and 601–1,200 residues, ESMFold up to 800 residues, Bases2Fastq workflows, single-cell RNA-seq workflows using KallistoBUStools, Salmon Alevin-fry and STARsolo, and Sentieon long-read ONT and PacBio HiFi workflows.[65] AWS reports that Sentieon made its DNAseq and TNseq pipelines available as Amazon Omics Ready2Run workflows for germline and somatic variant calling.

Sentieon states that these pipelines provide results matching Broad Institute GATK Best Practices pipelines, and that DNAscope has fewer variant-calling errors and a faster runtime than GATK; production use requires an active Sentieon license.[66] An AWS example WDL short-read variant workflow uses BWA-MEM for alignment, samtools for sorting/indexing and bcftools for calling.[67]

HealthOmics itself is not a fixed bioinformatics executable catalog. It is a managed execution service that runs the containers and scripts selected by the customer or workflow publisher. An enterprise must therefore own the software bill of materials: container digest, reference version, tool version, license status, validation evidence and change control. HealthOmics assists this control by retaining container SHA-256 digests and S3 ETags in immutable run records.[68]

AWS also supports specialized analysis paths outside the core HealthOmics catalog. DRAGEN v4.0 is available through AWS Marketplace and can use EC2 F1 instances and AWS Batch; its DNA pipeline supports BCL-to-FASTQ, alignment, sorting, duplicate marking and variant calling.[36] NVIDIA Parabricks can be deployed through GPU-enabled container infrastructure. These options provide performance flexibility but add licensing, hardware, container and workflow-operation responsibility.

For performance, AWS has a managed HealthOmics PacBio HiFi WGS variant-pipeline deployment in which HealthOmics manages WDL execution, container orchestration, infrastructure and S3-based data storage.[35] In the cited configuration, DeepVariant required 64 CPUs and 239 GB RAM and could use a GPU; GPU DeepVariant reduced completion time by 8.5% against the CPU configuration.[35] That result supports HealthOmics as a managed execution environment for a real variant pipeline.

A separate AWS EC2 DRAGEN benchmark processed 30× GIAB FASTQ genomes in approximately 48 minutes on f1.16xlarge and approximately 95 minutes on f1.4xlarge in us-east-1.[36]Derived — At 48 minutes per genome, one f1.16xlarge-equivalent execution path consumes 80,000 instance-hours for 100,000 genomes annually, requiring an average of 9.13 continuously occupied instances over a 365-day year. This is a DRAGEN-on-EC2 capacity model, not HealthOmics runtime.

AWS offers two temporary workflow-storage modes. Dynamic storage scales with actual usage and has no minimum provisioning. Static storage is a pre-provisioned Lustre file system with a 1,200-GiB minimum, baseline throughput of 200 MB/s per TiB and burst throughput up to 1,300 MB/s per TiB. Static storage can accelerate high-concurrency, I/O-heavy pipelines but creates a cost floor and requires capacity planning, including 7% base filesystem overhead.[8][69] This is a material operational choice for a large WGS program.

HealthOmics is HIPAA-eligible, as is HealthLake.[18][1][70] HIPAA use requires execution of AWS’s Business Associate Addendum and restriction of PHI processing, storage and transmission to services listed as HIPAA-eligible under the BAA. AWS encrypts HealthOmics data and metadata at rest and in transit; HealthOmics also provides run-level audit metadata and CloudWatch logs.[11][68] The biotech remains responsible for the complete HIPAA program: identity and role design, key management, logging, incident response, retention, access review, approved software, PHI-safe metadata and vendor governance.

AWS states that in February 2021 it adopted strengthened contractual commitments for protecting customer data. AWS says these commitments apply to all customer data it processes, including data not transferred outside the EEA, and are automatically available through a Supplementary Addendum to the AWS DPA incorporated in the AWS Service Terms.[71] AWS also describes the July 10, 2023 EU–US Data Privacy Framework adequacy decision for qualifying certified recipients and recognizes Standard Contractual Clauses and Binding Corporate Rules as transfer tools.[12] Genetic data remains GDPR special-category personal data.Judgment — The controller must document an Article 6 lawful basis, an Article 9 condition, purpose limitation, data minimization, retention, security measures and the applicable Chapter V transfer mechanism for every transfer outside the EEA. Selecting an EU Region reduces unnecessary movement but does not replace this legal analysis.

China is the decisive constraint for AWS. AWS China is a separate cloud partition with Beijing and Ningxia Regions, and the AWS China Region table dated February 28, 2026 does not list HealthLake or HealthOmics among the listed services.[72] China-related genomic projects must address PIPL, the Data Security Law, Cybersecurity Law and the Human Genetic Resources regime.

China’s HGR framework covers HGR Materials and HGR Information generated from those materials, including genomic and sequencing data. The Implementation Rules took effect on July 1, 2023, and primary HGR oversight shifted from the Ministry of Science and Technology to the NHC in 2023.[15] HGR management shifted to the National Health Commission in May 2024, while CAC leads the cross-border data-transfer framework.[73]

China’s cross-border rules depend on data classification, exporter status and cumulative annual volumes. CAC security assessment is required for a CIIO exporting PI or important data; for important-data exports; and for non-CIIO exports reaching at least 1 million individuals’ PI or at least 10,000 individuals’ sensitive PI in a year.[13][74][73] For a non-CIIO below security-assessment thresholds, exports of 100,000 to fewer than 1 million persons’ PI, or fewer than 10,000 persons’ sensitive PI, require a CAC standard contract plus PIPIA filing or a certification route.[15] Genetic and clinical health information are generally sensitive PI.[15]

China’s HGR regime also applies a security-review category when HGR information provided to foreign entities includes genome-sequencing information resources of more than 500 cases, important genetic families, specific regions, or other situations affecting China’s public health, national security, or social and public interest.[75] A 100,000-genome Chinese program exceeds the stated 500-case genome-sequencing threshold. Foreign-party classification can depend on establishment, actual control and ownership structure, including 50% or more indirect ownership.[14][75]

**Conclusion — AWS can satisfy HIPAA, GDPR and China-law requirements simultaneously only through separate legal and geographic processing zones, not through a pooled global HealthOmics environment.** A US HIPAA zone uses BAA-covered services and HIPAA controls; an EEA zone uses GDPR controller and processor safeguards; and a China zone requires legally authorized China-local infrastructure and Chinese institutional governance using locally available components rather than a confirmed China deployment of HealthLake or HealthOmics. Any cross-zone sharing is limited to legally authorized, minimized outputs, with China-originating genomic data retained in China unless the specific HGR and CAC/PIPL path has been completed.[11][12][72][76][77][13][75]

Azure Blob economics require transaction modelling as well as capacity modelling. Copying a blob to another account incurs source-tier retrieval and a read operation, and copying it to another Region also incurs network egress. A Blob Service download incurs one read operation per blob, whereas an Azure Data Lake Storage endpoint download incurs multiple read operations because it reads 4-MiB blocks; Cool, Cold and Archive reads also incur per-GiB retrieval charges.[52]

Federation distinction. Full federation federates both data and compute access over distributed compute and databases so users can query and jointly analyze data. Partial federation federates either data access or compute access. Federated learning is distinct: researchers train machine-learning algorithms collaboratively on dispersed data, including health records.[175]

Federated architectures still exchange intermediate machine-learning models or aggregated analysis results. Federated-learning models face inference attacks, feature leakage and data-poisoning risks, while federated data access creates risks when new users or code enter a data controller’s computing environment. Federated platforms require logging and auditing of platform and user activity and data/code export controls, including airlocks.[175]
